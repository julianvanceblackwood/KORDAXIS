# Security Policy

## Reporting vulnerabilities

Do not open a public GitHub issue for suspected security vulnerabilities.

Use GitHub's private vulnerability reporting mechanism.

Reports should contain, where possible:

- affected component
- affected version or commit
- technical description
- security impact
- reproduction conditions
- relevant logs or evidence
- proposed mitigation, if known

Do not include real third-party credentials, personal data, production secrets, or unrelated sensitive information.

## Scope

Security reports may include vulnerabilities involving KORDAXIS source code, CI/CD workflows, repository automation, evidence integrity, authorization boundaries, provenance validation, parser behavior, simulation isolation, and decision safety mechanisms.

Synthetic attack scenarios are intentional test material and are not vulnerabilities by themselves.

## Supported version

During Generation 0, only the current `main` branch is supported.
